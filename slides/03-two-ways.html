> Set up a maintainable landing-page project for [BRAND / PRODUCT]. Use [REFERENCE WEBSITE] as a visual reference for the product and brand direction. Before building, inspect the reference website and extract its useful design language—composition, hierarchy, colors, typography, spacing, layout, surfaces, imagery, motion, responsive behavior, and accessibility patterns—then adapt those decisions to my product, audience, promise, and brand voice. Do not copy its brand, words, assets, or implementation. Use the existing project stack when one is present. For a new project, use Vite 8 + React 19 + TypeScript + Tailwind CSS 4 via @tailwindcss/vite. Scaffold it with:\n\nnpm create vite@latest . -- --template react-ts\n\nThen install the project dependencies and keep package.json, scripts, and configuration consistent with that stack. Before writing page code, create a clear scaffold with separate, reusable components, content, styles, assets, routes, and configuration. Use CSS motion unless the project explicitly needs an animation library. Document the combined product direction, desired page structure, and reference-derived design decisions in a reusable DESIGN.md. Treat the provided design system as the source of truth for visual language and tokens, while using my desired structure, sections, content hierarchy, and user flow to shape the page. Combine both deliberately: keep the structure easy to understand and the visual system consistent. Encode the same source-of-truth tokens in the Tailwind theme and CSS variables: colors, fonts, type scale, spacing, radii, borders, shadows, breakpoints, and motion. Build an original responsive landing page from that system with reusable sections and content—not one-off styling. Keep the structure easy to extend and hand off. Run the existing lint and build commands, test desktop and mobile in the browser at 1440px and 390px widths, check console errors, overflow, accessibility, and motion, then fix visible issues and summarize the final structure.
